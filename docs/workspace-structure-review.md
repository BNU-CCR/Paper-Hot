# Workspace Structure Review

Date: 2026-06-30

This review separates two different questions:

- Is the Git repository clean enough for collaboration?
- Is the local project folder readable enough for a human to work in every day?

The repository is now mostly clean. The remaining problem was local workspace readability: root-level files mixed product code, runtime data, Feishu login artifacts, Codex/Claude tool state, secrets, and Python packaging output.

## Current Diagnosis

The root folder currently contains four types of things:

| Category | Examples | PM assessment |
| --- | --- | --- |
| Product assets | `src/`, `web/`, `public/`, `config/`, `tests/`, `docs/` | Keep at root. These are the project surface area. |
| Runtime state | `data/papers.db`, `data/reports/` | Keep under `data/`, but never commit database/report outputs. |
| Local credentials | `key.env` | Acceptable short term because `src/config.py` reads this path directly. It must remain ignored. |
| Local tool artifacts | Feishu QR PNGs, `skills-lock.json`, `.agents/`, `.claude/`, `.codex/` | Should not be visually mixed with product assets. Move non-hidden artifacts into `.local/`. |
| Build artifacts | `journal_tracker.egg-info/` | Generated by editable install/build tooling. It is ignored and can be removed after confirmation. |

## Changes Made

- Created `.local/feishu/` for Feishu QR code images.
- Created `.local/tool-state/` for local tool lock files.
- Moved root Feishu QR PNGs into `.local/feishu/`.
- Moved `skills-lock.json` into `.local/tool-state/`.
- Added `.local/` to `.gitignore`.

No source code, database, public JSON, or workflow behavior was changed.

## Target Structure

The intended human-readable structure is:

```text
.
├── README.md                 # project entrance and current status
├── CLAUDE.md                 # agent notes for local AI assistants
├── pyproject.toml            # Python package metadata
├── config/                   # journals, prompts, settings
├── src/                      # workflow implementation
├── tests/                    # Python tests
├── web/                      # static website UI
├── public/data/              # website JSON snapshots
├── docs/                     # current docs and archive
├── scripts/                  # helper scripts
├── data/                     # local runtime state, ignored
└── .local/                   # local-only tool artifacts, ignored
```

## What Still Looks Messy

### `journal_tracker.egg-info/`

This is the remaining root item that looks like a project folder but is not one. It is generated by Python packaging tools, already ignored by Git, and can be deleted safely in normal circumstances. If the editable install needs it again, `py -m pip install -e .` will regenerate it.

Recommended action: delete it after confirming we are comfortable removing generated local artifacts.

### `key.env`

This is still root-level because the current config loader reads `project_root / "key.env"`. From a PM/readability perspective, a better long-term home would be `.local/key.env`, but that requires changing config code and tests.

Recommended action: keep it for now. Move it only in a dedicated config cleanup step.

### `web/` and `public/`

The split is technically reasonable for a static site:

- `web/` is the website app.
- `public/data/` is the data artifact consumed by the website.

If the product grows, a future structure like `apps/site/` could be cleaner, but moving it now would create churn across commands, docs, and tests without much immediate benefit.

Recommended action: keep the current split until the site becomes a larger app.

## Documentation Rule Going Forward

There should be only one active document for each management purpose:

| Purpose | File |
| --- | --- |
| Project entrance and current state | `README.md` |
| File/folder responsibilities | `docs/project-map.md` |
| Active TODO and phases | `docs/roadmap.md` |
| Historical plans/specs | `docs/archive/` |
| Workspace cleanup rationale | `docs/workspace-structure-review.md` |

New planning notes should update `docs/roadmap.md` instead of creating another root-level TODO file.
