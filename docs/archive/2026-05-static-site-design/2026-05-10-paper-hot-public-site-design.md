# 计算传播论文 HOT 公开站设计

日期：2026-05-10

## 背景

当前项目已经具备论文采集、AI 筛选、本地 SQLite 存储和通知能力，但主要以命令行和私有数据为中心。新的目标是把筛选后的论文结果包装成一个可公开部署、可分享给同门、未来也可面向小红书等公开平台传播的 AI 自动应用。

参考对象是 AI HOT。要学习的是它的信息组织方式和界面气质：窄侧栏、双主题、日期时间线、精选信息流、标签、分数、摘要和推荐理由。不能直接复制品牌与具体实现，应该转译为“论文情报站”。

## 产品定位

第一版定位为：公开论文情报站 + 私有筛选发布流。

公开站只展示经过确认发布的筛选结果，默认展示 `High` 和 `Medium` 论文。不公开筛选 Prompt、关键词配置、期刊配置、API Key、Low 论文、内部备注、调试日志和未确认候选项。

对外表达建议为：“AI 辅助整理的计算传播论文精选”。不解释内部筛选机制和算法细节。

## 用户与场景

主要用户：

- 课题组同门：快速了解计算传播相关新论文。
- 组会参与者：按周查看精选论文和主题趋势。
- 外部学习者：通过公开链接、小红书分享或 RSS 获取论文信息。
- 项目维护者：本地维护配置、运行筛选、校正结果并发布。

核心场景：

- 每日或每周查看最新精选论文。
- 通过主题标签浏览 LLM、算法推荐、社交媒体、虚假信息、NLP、平台治理等方向。
- 打开单篇论文详情，查看摘要、推荐理由、来源链接和 DOI。
- 分享单篇论文或周报链接给同门。
- 后续扩展为 RSS、周报、分享卡片和 Agent/API 入口。

## 信息架构

公开页面：

- `精选论文`：首页，AI HOT 风格时间线信息流。
- `主题标签`：按主题聚合论文。
- `周报归档`：每周自动形成精选合集。
- `论文详情页`：单篇论文的完整公开信息。
- `RSS / 订阅`：后续提供 RSS、JSON feed 或 Agent 读取入口。
- `关于`：说明项目范围、更新频率和公开数据边界。

私有侧：

- 期刊和关键词配置。
- Prompt 与筛选策略。
- API Key 和采集任务。
- 人工校正、发布开关、内部备注。
- Low 论文和未发布候选项。

## 视觉方向

采用方案 B：论文情报工作台型 + AI HOT 双主题系统。

布局：

- 桌面端左侧固定窄侧栏，右侧主内容区。
- 移动端侧栏折叠为顶部导航。
- 首页顶部为筛选与搜索面板，下方为日期时间线信息流。
- 论文卡片控制在中高信息密度，避免营销页式大图和大段说明。

主题：

- 支持 `light`、`dark`、`system` 三段切换。
- 默认跟随系统。
- 主题切换放在侧栏底部，样式参考 AI HOT 的月亮 / 屏幕 / 太阳三段式控件。

浅色模式：

- 背景为冷灰蓝，例如 `#f7f9fc`、`#eef3f8`。
- 卡片为白色或半透明白，搭配低对比边框和轻阴影。
- 标题使用深蓝黑，正文使用灰蓝。
- 推荐理由使用浅绿色提示条。
- 时间线使用淡灰竖线和 cyan/green 节点。

深色模式：

- 背景为深蓝黑渐变，例如 `#060814`、`#0b1020`。
- 卡片为半透明深色 surface。
- cyan 用于品牌、选中态、节点和链接强调。
- High 用绿色，Medium 用琥珀色。

品牌：

- 可选名称：`Paper HOT`、`CC Paper HOT`、`Comm Paper HOT`。
- Logo 采用字母 + 小轨道圆点结构，借鉴 AI HOT 的信息站气质，但不直接复制。

字体：

- 中文标题可使用宋体/衬线风格提升学术感。
- 正文使用清晰无衬线。
- 标签、分数、时间可使用等宽字体。

## 论文卡片结构

列表卡片信息层级：

1. 相关性与分数，例如 `High 92`、`Medium 74`。
2. 标题。
3. 作者、期刊、年份或发布日期。
4. AI 摘要。
5. 推荐理由提示条。
6. 主题标签。
7. 原文、DOI、详情链接。

详情页信息层级：

- 标题。
- High/Medium、分数、标签。
- 作者、期刊、发表日期、DOI。
- AI 摘要。
- 推荐理由。
- 可能的研究方法、数据来源、关键词。
- 外部链接。
- 同主题论文推荐。

第一版不放论文封面图。论文通常没有稳定视觉资产，强行配图会降低一致性。后续小红书分享卡片可以单独生成视觉图。

## 数据发布流程

第一版采用私有生成 + 公开静态站。

流程：

1. 本地维护 `config/journals.yaml`、关键词、Prompt 和 API Key。
2. 追踪脚本采集论文并写入 `data/papers.db`。
3. AI 筛选生成 `relevance`、`summary`、`reason`、`tags`。
4. 增加发布导出步骤，仅导出公开字段。
5. 公开站读取 `public/data/papers.json`、`weekly.json`、`tags.json`。
6. 部署到 Vercel、Cloudflare Pages 或 GitHub Pages。
7. 后续可由 GitHub Actions 或本地一键发布自动刷新。

公开数据字段：

```json
{
  "id": "paper-2026-001",
  "title": "...",
  "authors": ["..."],
  "journal": "...",
  "published_date": "2026-05-10",
  "relevance": "High",
  "score": 92,
  "summary": "...",
  "reason": "...",
  "tags": ["LLM", "算法推荐"],
  "doi": "...",
  "source_url": "...",
  "detail_slug": "..."
}
```

不导出字段：

- 筛选 Prompt。
- 期刊、关键词和私有配置。
- API Key。
- Low 论文。
- 内部备注。
- 未确认发布候选项。
- 调试日志。

## 技术路线

第一阶段建议选择静态公开站：

- 保留现有 Python 采集与筛选系统。
- 增加导出脚本，将 SQLite 中可公开论文导出为 JSON。
- 新增静态前端读取 JSON 渲染页面。
- 使用 Vercel、Cloudflare Pages 或 GitHub Pages 部署。

第二阶段再增加私有后台：

- 发布开关。
- 摘要、标签、推荐理由人工校正。
- 周报生成。
- 小红书分享卡片生成。

第三阶段扩展为信息服务：

- RSS。
- JSON feed。
- 周报邮件。
- Agent/API 入口。
- 更细的主题页和检索能力。

## 验收标准

第一版完成后应满足：

- 公开站只展示 High/Medium 或手动标记为发布的论文。
- 不暴露 Prompt、配置、API Key、Low 论文和内部备注。
- 首页有 AI HOT 风格的侧栏、筛选面板、日期时间线和论文卡片。
- 支持 light/dark/system 三段主题。
- 单篇论文有可分享 URL。
- 主题标签可浏览。
- 可从 SQLite 生成公开 JSON。
- 部署后可公开访问。

## 待定问题

- 公开站名称最终选择：`Paper HOT`、`CC Paper HOT` 或其他名称。
- `Medium` 是否默认公开，还是需要手动发布确认。
- 是否第一版就生成周报页，还是先只做首页和详情页。
- 部署平台优先选择 Vercel、Cloudflare Pages 还是 GitHub Pages。
- 是否需要给课题组内部保留一个未公开预览地址。
